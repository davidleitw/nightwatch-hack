# control 09:加分:前端嵌入、對話模式、環形落地、Grafana 第二來源

## 為什麼要有這段
四件各自獨立的加分,協調者說先做哪一項。前端嵌入是 demo 一定要的(整個 NightWatch 變成一個執行檔);其他三項有空才做。

## 目標
- 嵌入(一定要;等前端 07 放好嵌入用的檔案再做):control 把前端的 build 產物包進執行檔,非 API 路徑回單頁應用,找不到就回首頁,不快取;沒有 build 產物時維持「前端未 build」。交叉編譯照樣要過。
- 對話模式(有空):同一組工具與靜態前綴(另一個 cache key),提問時刻當 t=0,預算比排查小;事故進行中與同時多個對話都要拒絕;回覆帶用了哪些工具。
- 環形落地(有空):定期把環形原子寫檔、啟動時讀回;跟現在差太久的下一張快照要標出缺口並寫 journal。
- Grafana 第二偵測來源(有空):內部埠收 Grafana 的告警 webhook,忽略資料源類的告警;事故沒開就以 grafana 為來源開事故,已開就記為佐證。

## 契約在哪
- `../contracts/API.md` §3(chat、grafana、`/` 的行為與錯誤碼)§5(快照的缺口欄位)
- 前端的嵌入檔:`../console/embed.go`(前端 07 產出),control 的 go.mod 用 replace 指到 `../console`

## 怎麼算做完
- 嵌入:`go build` 後開 control 的埠看到卡片頁,`CGO_ENABLED=0 GOOS=linux GOARCH=arm64` 交叉編譯過。
- 對話:事故進行中與第二個同時對話各拿到契約的 409;正常提問回中文回覆與工具清單。
- 落地:重啟 control 後歷史不從零開始;缺口那張快照有標記。
- Grafana:資料源告警被忽略,一般告警會開事故或佐證。

## 測試
只寫契約邊界與主線:每做一項補該項的一兩個邊界(對話的兩種 409、讀回後的缺口標記、Grafana 的兩條路徑)。

## 不做什麼
沒被協調者點名的項目;任何改契約的事。

## 接線點
嵌入做完,協調者的 compose 只需要一個 control 容器,demo 網址從 dev-server 換成 control 的埠。對話要前端有對話分頁才用得到,先問協調者;Grafana 要 compose 多一個容器,沒時間就不做。
