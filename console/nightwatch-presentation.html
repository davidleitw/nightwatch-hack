01 / THE PROBLEM

告警之後，仍要回答三個問題

服務關聯

哪裡出現異常？

單一錯誤訊息之外，還需要看見相鄰服務與量測變化。

調查依據

為什麼這樣判斷？

結論需要對應查詢結果，讓人能回頭檢查證據。

後續交接

已經查過什麼？

保留工具活動與調查上下文，避免只剩一句結論。

NightWatch 將觀測、調查與保存紀錄串成同一個工作流程。

問題定義依 BACKEND.md 的角色分工，以及 console/README.md 的調查工作台功能整理。

02 / ARCHITECTURE

Monitor 觀測，Guard Room 彙整，Watcher 調查

依 BACKEND.md 與 investigation 介面文件簡化；Watcher 透過工具讀取觀測，圖中箭頭表示資料流。自動處置屬專案方向，非本次已驗證能力。

03 / INVESTIGATION

Watcher 用工具查證，再提交結構化報告

get_graph

取得服務觀測圖

list_graph_snapshots

查閱過去快照

get_node_detail

查看節點細節

search_logs

搜尋應用日誌

submit_report

提交有證據引用的結論

調查發現與假設
支持證據與反證
限制與下一步

證據不足時，可明確回報
conclusion: inconclusive

依 control/AGENT-REPORT-API.md。此為 Live Guard Room 工具介面；帶 query selector 的來源只提供 get_graph 與 submit_report。本次未執行真實模型。

04 / WORKSPACE

同一個畫面，看見狀態與調查進度

版面示意，依 console/src/investigations.js 整理，非即時截圖。觀測健康與調查狀態各自更新；心跳不代表新量測，缺資料不填示意數值。

05 / TRACEABILITY

一次調查，留下可重新查閱的完整紀錄

REPORT

報告

摘要、調查發現與假設，連同限制和下一步保存。

EVIDENCE

工具證據

保存模型實際收到的觀測，透過證據 ID 追溯引用。

CONTEXT

活動與上下文

查閱工具事件、模型可見對話與累計使用量。

最新後端介面提供整次調查 JSON 匯出；中斷紀錄標示完整度。

依 control/AGENT-REPORT-API.md：GET /api/investigations/{id}/export。新結構化報告的完整前端呈現仍待接線；匯出與真實模型整合本次未驗證。
